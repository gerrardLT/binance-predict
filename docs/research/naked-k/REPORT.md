### 3.2 口径对应关系（双 lens 成立的地基）

| 概念 | 定义 | 代码依据 |
|---|---|---|
| `win_rate`（次根方向） | 第 t+hz 根 **open→close** 方向是否等于押注方向 | `discovery/targets.py:64,80-82` |
| `cum_dir_win_rate`（累计方向） | `sign(ret)`，`ret = d*(c[t+hz]-c[t])/c[t]`（当根 close → t+N close，含跳空） | `targets.py:85` |
| abs lens | `dirup_h` / `dirdn_h`：次根**绝对**收阳/收阴 → 与预测市场结算口径同构 | `main.py:632-639`、`trade_settler.py:4-11` |
| rel lens | `continuation_h` / `reversal_h`：次根**相对信号根**同向/反向 | `targets.py` 既有目标族 |
| 主判决 lens | **只由注册表 `bet_side` 声明**（`up`/`down`→abs，`none`→rel），单一口径源 `lens_of()` 下沉至引擎，不因数据稀疏漂移 | `local_naked_k_engine.py` |

> **两个基准不同的列严禁混用**：`win` 是次根 open→close，`ret` 是当根 close→t+N close。
> 报告与 `findings.csv` 全程分列，正文不使用"胜率"裸词——一律写"次根方向命中率"或"累计方向命中率"。
> 实测两者背离程度：1,214 个可比格子中位数差 1.57pp，最大 100pp（后者全是 `n=1` 的退化样本，见 §6.4）。

平盘处理：`targets.py:76` 的 `base_valid` 要求当根与次根 `dir != 0`，**严格平盘的整条样本被剔除**；
doji 类形态用 `body/range ≤ 0.1` 判定（不要求 `c==o`），故本任务的可用样本损失率远低于全平盘口径。

### 3.3 全局 FDR 与漏斗纪律

- 族内校正：`(tf, window, lens, segment)` 共 **54 族**，q = `DEFAULTS["fdr_alpha"]` = 0.1。
- 全局校正：三周期 × 双 lens × 三窗口 × 全 horizons 的 holdout p 值汇为一池 **6,651 个**同池校正。
- 总 p 值账本：**19,879 个**（discovery 6,721 / validation 6,507 / holdout 6,651）。
- 绕开 `merge_r3` 的 `n_min_l2=200` 静默过滤：本任务**每个形态每格都出数**，低频格子打标签而非丢弃。

### 3.4 ⚠️ 独立性声明（硬要求）

1. **9 个格子不是 9 个独立样本。** 360d 与 180d 是 720d 的**时间真子集**，5m/15m/1h 共享**同一条 BTC 价格路径**。
   因此本报告**禁止并从未使用**"在 9 种设定中有 X 种复现"这类表述。
2. **判决只认 720d 冻结 holdout**（`oos_validator.py:145` 的"holdout 只触碰一次"纪律）。
   360d/180d 仅用于估计**估计量随样本长度的稳定性**；三周期一致性仅作**方向性佐证**，不叠加计票。
3. 实测稳定性（不是复现率）：同掩码同 lens 同 target 的 holdout lift 符号保持率
   **360d vs 720d = 935/1199 = 78.0%**；**180d vs 720d = 797/1156 = 68.9%**；**5m~15m 跨周期 = 173/288 = 60.1%**。
   → 即：把窗口缩短一半，约 1/5 的效应符号会翻；跨周期看，约 4 成会翻。这本身就是"单一信号被切成多格看会很脆"的直接度量。
4. **口径一致性的保障强度**：`.gitignore:39` 忽略 `output/` → CI 拿不到 CSV →
   `tests/test_kline_shadow_detector.py:50-51` 的 `full_env` 测试组在 CI 上**整组 skip**。
   故本报告的口径一致性**仅由本地验证 + `baseline.json` 哈希基线保证**，不得声称"CI 已把关"。

  仍被合并——因为命中集合塌缩到只剩 1~2 根，与同族跳空类判据落在同样的 K 线上；
  而去重键只取 `mask[:i1]`（**discovery 前缀**，口径同 `combo_search.py:23-25`）。
  反例：`NK-T1-23`@1h 同为 0 命中，却作为“代表全零掩码”**存活**（先到先得），

  所有 90 条都完成了表达式展开与掩码计算**（`n_exprs_before_dedup=100` 三周期一致）。

→ 业务结论：**BTCUSDT 永续 7×24 连续交易，跳空类形态在 15m 以上基本不存在**（720d 内 1h 级别整根跳空 **0 次**）；
  因此 `NK-T1-37/38`（跳空缺口）只在 5m 可测，`NK-T1-28`/`33`/`35` 只在 5m/15m 可测。
  **“高周期上这类形态根本不发生”本身就是一条结论**，不应被误读为“测了不行”。
→ 另：`ledger.json.oos_skipped.1h` 有 **10 条** (mask,target) 因 discovery 段零命中未进 `run_oos`
  （理由同为“不可判方向先验”）；5m/15m 各 **0 条**。
- 360d/180d 的"实际出裁决 = 0" 是**设计而非缺陷**：`run_oos`（含 bootstrap）只在 720d 上跑，以守住 holdout 只触碰一次。
- 功效标签口径：`min_detectable_effect = 1.2435/√n`（80% 功效、α=0.05 单侧），`TESTABLE` 要求 MDE ≤ 5.0pp；
  `UNTESTABLE` = `n_holdout < 60`（`DEFAULTS["n_min_holdout"]`）——**仍出数但明确标注"样本不足，不构成结论"**。

**读这张表的正确方式（防误读，务必先看）**：

> `REACHABLE_ROBUST` 一列说明"数学上有多少掩码有机会被判 ROBUST"。1h 的 `ROBUST` 需要
> `n_holdout ≥ 120` ⇒ **命中率至少 3.48%**；而 1h 上绝大多数形态 720 天只出现几十次。
> 所以 **1h 上大量 `WEAK`/`UNTESTABLE` 是统计功效不足的必然结果，不是"形态无效"的证据**。
> 反之 5m 上出现大量 `REJECT` 才是有信息量的负结果。

## 7. 副口径经济账（四层报价 + 报价曲面实测）

### 7.1 闭式与常数

费用与滑点取 `backtest/stats.py:11-12,18-20`：`FEE=0.02`、`PREMIUM=0.01`。

- 可接受入场价上限：`q_max(p) = (1-FEE)·p − PREMIUM = 0.98p − 0.01`
- 打平胜率：`p*(q̄) = (q̄ + PREMIUM)/(1 − FEE)`

**0.5204 不是可交易门槛。** `test_discovery_pipeline.py:83` 断言的 52.04% 与
`oos_validator.py:173` 的 `ev_at_0.50` 都建立在"入场价恒为 0.50"的理论假设上，
而 `db/models.py:761` 原文推翻了它：*「盈亏平衡胜率 p\* = (entry+0.01)/0.98 随报价漂移…
（实测记录期开盘价中位 DOWN=0.615 而非 0.5）」*。故本报告**四层并列，从乐观到保守**：

| 层 | q̄ | 打平胜率 p\* | 性质 |
|---|---|---|---|
| L1 名义 | 0.500 | **52.04%** | ⚠️ 仅**名义参照**（被 `models.py:761` 批评为理论假设） |
| L2 记录期实测 | 0.615 | **63.78%** | 本项目记录期开盘价中位（DOWN 侧） |
| L3 延迟入场实测 | 0.730 | **75.51%** | S5 延迟入场三注入场价 0.89/0.46/0.84 的实测（`local_s5_real_quote_ev.py:6-8`） |
| L4 报价曲面实测 | 见 §7.2 | 51.02% ~ 53.06% | 本次从样本文件重算的**开盘桶（桶 0）**中位数 |

### 7.2 报价分布实测（而非只用常数）

源：`prediction_market_samples_online_20260819.json`，167,702 条（5m 136,236 / 15m 31,466），无缺失价、无跨周期污染。

| 周期 | 样本 | 独立周期数 | 跨度 | 桶 0 中位 q̂（up / dn） | 折算 p\* |
|---|---|---|---|---|---|
| 5m | 136,236 | 6,850 | **23.78 天** | **0.51 / 0.49** | 53.06% / 51.02% |
| 15m | 31,466 | 570 | **5.92 天** | **0.50 / 0.50** | 52.04% |

**必须披露的三条限制**（`quote_surface.json.caveats` 原文要点）：

1. **样本跨度极短**（5m 23.78 天 / 15m 5.92 天），且绝大多数数据点落在 08-19 之后的**单一 regime**。
2. `up_price + down_price` **不逐条恒等于 1**：均值 1.000013，但 min 0.23 / max 1.82；
   `|dev|>0.01` 占 11.05%、`|dev|>0.05` 占 1.71%（5m）。偏离**大致对称**
   （`frac_gt_1p01`=2.94% ≈ `frac_lt_0p99`=2.94%）→ 判定为**两侧报价快照不同步的噪声，不是可提取的做市抽水**；
   因此 **`PREMIUM=0.01` 仍是外生滑点假设，不是市场事实**。
3. **L4 与 L2 冲突（0.50 vs 0.615），且这是 regime 差异不是数据错误**：
   L2 来自 `models.py:761` 的记录期，L4 来自 08-19 后的快照期。
   → 主经济账**用闭式与四层区间做判定，不用 L4 点估计替代 L2**；两层的差异本身就是结论的一部分。

### 7.3 可交易性计数（这是全报告最重要的一张表）

计数范围：**主 lens × 720d × 5m/15m × horizon=1**（只有这个组合与 holdout 判决同构）= **168 行**。

## 9. 阈值敏感性（±1 档重跑 + 翻转清单）

**动机（前例）**：`scripts/local_candle_def_scan.py:84-91` 已用 6 套定义（D0~D5，影线倍率与振幅下限不同）

## 10. 执行过程中发现的既有缺陷（非本任务引入，本任务未修改任何 `src/`）

计划「绝对不动区」禁止修改 `src/binance_predict/discovery/**`。以下三项因此**只记录、不修复**。

### 10.1 `targets.py` 的 MFE/MAE 量纲错误（生产既有）

- 文档意图（`targets.py` 头注 L10）：*「MFE/MAE … 以当根前置 ATR 归一」* → 应得 **ATR 倍数**（量级 ~1e-2）。
- 实现（`targets.py:86-87`）：`mfe = np.where(d > 0, max_h - c, c - min_l) / (atr_abs * c)`
  而 `features.atr_series()` 返回的已是 `atr * kl.o`（**绝对美元**）→ 分母又乘了一次价格（BTC ~1e5），
  实际单位变成 **1/美元**。
- **实测证据**：本任务 `holdout_mfe_mean_atr` 最大值 `1.368e-04`、`holdout_mae_mean_atr` 最大 `1.231e-04`；
  而**冻结产物** `output/kline_discovery_15m_720d_v2/all_tests.csv` 的同名列范围是 `3.787e-06 ~ 3.056e-05`
  → **同一量级的偏小在既有生产产物中早已存在，非本任务引入**。
- **自检盲区（为什么没被拦住）**：本任务的 `synthetic_target_check()` 与
  `tests/test_discovery_pipeline.py` 的合成断言都是**复刻实现算期望值**，而非按文档意图独立推导；
  于是"3 根合成 K 线 + ATR=3"这种手算例两边会同时错，测试通过却拦不住量纲缺陷。
- **对本报告的影响**：**MFE/MAE 两列在全部结论中一律不使用**（§5.3 的逐条块里刻意省略）。
  `payoff_ratio` / `expectancy` 走的是 `ret` 收益路径，不受此缺陷影响，正常使用。
- **建议处置（需另行授权）**：改为除以 `atr_abs`（绝对美元）或 `atr_pct * c`；
  并同步修正 `v2` 冻结产物与依赖该列的历史报告。
