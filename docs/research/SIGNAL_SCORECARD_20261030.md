# 最终信号记分卡（2026-10-30，审计后）

## 0. 修正：这是 1 条规则，不是 2 个信号

之前把"UP 中价落在 0.65–0.80"与"UP 中价落在 0.15–0.35"当成两个信号（E/F），是**按 UP 区间机械切分**的错误。
二元合约里 UP + DOWN = 1，所以：

- UP 中价 0.65–0.80 ⇒ **UP 是热门**，买 UP；
- UP 中价 0.15–0.35 ⇒ **DOWN 是热门**（0.65–0.85），买 DOWN。

两者都是"买热门"，只是热门恰好落在 UP 还是 DOWN。合并后样本翻倍、t 更高：

| | 热门=UP | 热门=DOWN | **合并（正式口径）** |
|---|---|---|---|
| 笔数 | 688 | 762 | **1,450** |
| 日均 | 6.2 | 6.9 | **13.1 笔/天** |
| 胜率 | 81.1% | 81.0% | **81.0%** |

| 净@1.9% | +4.14% | +3.63% | **+3.87%** |

| 月度 | — | — | +1.4 / +5.2 / +5.0 / +3.9（4/4） |

**正式定义**：`t ∈ [855s, 900s)`，且热门一侧的中价 ∈ `[0.65, 0.85)` → 买入热门（UP 或 DOWN），持有到结算。

## 二、下单延迟与偏移量（审计补充，2026-10-30）

### 2.1 延迟会吃掉多少

把成交价从"触发那一刻的 ask"换成"t0+Δ 秒后的 ask"，重算同一条规则（1,450 笔）：

| Δ（触发→成交） | 成交均价 | 净 ROI | t | 保留 |
|---|---|---|---|---|
| 0（理想） | 0.7662 | **+3.87%** | — | 100% |
| 0.3s | 0.7692 | +3.46% | 2.59 | 89% |
| 0.5s | 0.7715 | +3.15% | 2.36 | 81% |
| 1.0s | 0.7746 | +2.63% | 1.98 | 68% |
| 2.0s | 0.7790 | +1.88% | 1.41 | 48% |
| 3.0s | 0.7787 | +2.03% | 1.49 | 52% |
| 5.0s | 0.7852 | +1.24% | 0.89 | 32% |
| 10s | 0.7923 | **−0.97%** | −0.66 | 翻负 |

**每延迟 1 秒，净收益掉约 1.1pp。** 价格在最后 45 秒以约 **0.8 分/秒** 收敛（0.7662 → 0.7746 in 1s），
而这条规则的边际只有 3.9pp —— 延迟 3.5 秒就只剩 1/4。

分方向（Δ=0 → 2s）：

| 方向 | Δ=0 | Δ=0.5s | Δ=1s | Δ=2s |
|---|---|---|---|---|
| 热门=UP（688 笔） | +4.14% | +3.30% | +2.70% | +1.68% |
| 热门=DOWN（762 笔） | +3.63% | +3.02% | +2.57% | +2.05% |

热门=DOWN 衰减更慢（便宜侧挂单更厚、价格更慢）。

### 2.2 生产环境真实延迟

用真实成交单的 `quote_json.timestamp`（交易所报价时间）与 `created_at`（本地建单时间）相减：

| 指标 | 值 |
|---|---|
| 样本 | 1,221 笔 FILLED |
| 中位 | **1.79 秒** |
| P25 / P75 | 2.43s / 0.92s |
| P10 / P90 | 2.97s / 0.25s |

即：**从本地决定下单到交易所生成报价，中位约 1.8 秒**（例：开窗 900s → 本地建单 901.8s → 交易所报价 904.2s）。

把 1.8s 代进衰减曲线：**净收益 ≈ +2.0%（而非 +3.9%）**，容量受限日收益从 ~31 U/天降到 **~16 U/天**。

### 2.3 意味着什么

1. 这条规则本质是**速度套利**，不是"价格错配套利"——它赚的是"报价比现货慢一秒"的钱。
2. **必须在 1 秒内完成从看到盘口到下单**，否则只剩一半。现有生产链路 1.8s 的中位延迟已经偏慢。
3. 如果延迟压不下来，正确的做法不是硬做，而是**改用限价单**（挂 0.75 买，等别人来吃）——但那样会承担不成交风险，需要单独验证。
4. 上面所有 "+3.9%/+5.2%" 都是 **Δ=0 的理论上限**；**现实口径应写 +2.0%**。


### 2.4 限价单替代方案：已用数据否决

"延迟压不下来就挂限价单"，这个替代方案我做了回测：在触发时挂买单，之后任一快照的最优卖价 ≤ 挂单价即视为成交（有人以该价或更低卖出），持有到结算。

| 挂单价 | 成交率 | 成交后胜率 | 净 ROI | t |
|---|---|---|---|---|
| ask − 0.00（等于吃单，仅免手续费） | 100% | 81.0% | **+5.88%** | 4.3 |
| ask − 0.01 | 66% | **71.4%** | **−5.53%** | −2.8 |
| ask − 0.02 | 58% | 67.8% | −9.02% | −4.1 |
| mid − 0.01 | 58% | 67.4% | −9.55% | −4.3 |
| mid − 0.03 | 50% | 62.5% | −13.83% | −5.5 |

**结论：限价单被逆向选择吃死。** 挂低 1 分钱换来 34% 的不成交，成交的那些胜率从 81% 掉到 71%——
你只在"热门正在输"的时候才被成交。价格改善 1 分（≈1.4pp）远不能补偿胜率损失 10pp。

注意第一行：**如果手续费为 0，同样的吃单交易是 +5.88% 而不是 +3.87%** ——
即这 2pp 差价就是平台抽水。但吃单无法豁免，限价又过不了逆向选择，所以**只能吃单**。

### 2.5 那 1.8 秒花在哪：代码路径审计

`execute_signal_trade()` 的关键路径（`prediction_trading.py:2110` 起）：

```
async with self._trade_lock:          # ① 全局锁，所有通道串行
    await self._reserve_order_slot()  # ② 数据库写入
    await self.list_markets()         # ③ 分页拉市场列表，最多 5 次 HTTP ← 大头
    ...计算 token_id...
    quote = await self.get_quote()    # ④ HTTP → 币安
    ...护栏检查...
    result = await self.place_order() # ⑤ HTTP → 币安
```

三个可压缩项：

| # | 问题 | 代价 | 修法 |
|---|---|---|---|
| ③ | `list_markets()` **无条件**在下单关键路径调用，最多 5 页 | 估算 0.5–1.5s | 命中缓存就跳过；只在 cache miss 时刷新（已有 60s 后台预热） |
| ① | `_trade_lock` 是**全局锁**，同一时刻多个通道开火会排队 | 第 2/3 单各多等 1 个完整周期 | 锁只保护 token 刷新，不覆盖网络调用 |
| ④⑤ | quote → order 两次串行 HTTP | ~0.3–0.6s | 无法消除，但可把 ③ 省下的时间留给它 |

**预期**：改 ③+① 后，关键路径从 1.8s 降到 ~0.5s，衰减曲线对应 **+3.2%**（而非 +2.0%），
即**每天多赚约 50%**，且不用改任何策略参数。

**建议顺序**：先加计时日志（list_markets / get_quote / place_order 各自耗时），
确认 ③ 的真实占比，再动锁的范围——不要凭估算改生产代码。

把 1,450 笔按"仓位 25U（热门=UP）/ 100U（热门=DOWN）"记账，成交价取 t0+2s 的盘口（≈生产 1.8s），费率两种口径：

（111 天、13.1 笔/天、平均仓位 64U；实际费率指按价格递减的真实费率，均价 0.766 处约 0.63%/赔付）

**收益率取决于压多少本金——但绝对收益被容量锁死：**

| 本金 | 日收益率 | 日波动 | 观测最大回撤 | 年化（算术） |
|---|---|---|---|---|
| 1,000 U | +2.83% | 13.3% | **−44%** | ~1,030% |
| 2,000 U | +1.41% | 6.7% | −22% | ~515% |

**三个必须同时看的事实：**

1. **绝对上限 ≈ 28 U/天**：平均仓位 64U × 13.1 笔，盘口只吃得下这么多。资金加到 10,000U 也不会多赚一分，只是把收益率摊薄到 0.28%/天。
2. **日中位（+52U）高于日均（+28U）**：少数"100U 仓位全灭"的日子把均值拉低，说明收益分布左偏，不能只看均值。
3. **资金占用极低**：13 笔 × 45 秒 ≈ **10 分钟/天**，本金 99% 时间闲置。所以本金的作用不是"投入"，而是"扛回撤"——1,000U 本金遇到观测最差日会 −44%。

**不要引用年化复利**：2.8%/天 × 365 的复利数字没有意义——容量在 28 U/天封顶，复利假设一旦放大仓位就会撞上盘口深度。

## 四、必须一起读的限制

1. **E 的幅度对定义敏感**：`0.65–0.80 / t≥855` 是 +5.6%（t=2.6），但放宽到 `0.60–0.80 / t≥840` 只剩 +1.5%（t=0.75）。价位是平滑峰、时间单调（t≥780 +0.4% → ≥870 +11.3%），机制可信，**幅度不可信**。
2. **容量是走单估算**：E 只有 177 个市场、F 只有 125 个市场的完整盘口样本，真实成交可能更差。
3. **E/F 都是"55 秒内到期"的交易**：资金占用短，但下单延迟敏感；报价在这段时间最薄。
4. **没有实盘验证**：两条都还没有生产环境的小额成交样本。
5. E 的正收益依赖"能在 855s 后按当时 ask 成交"；若只成交到一部分，实际收益按比例缩。

## 五、一句话总结

> **可用信号只有 1 条：尾盘（t≥855s）买热门，热门价 0.65–0.85。**
> 13.1 笔/天，胜率 81.0%，**Δ=0 净 +5.2%、按生产 1.8s 延迟 +3.3%（保守费率 +1.9%）**，日聚类 t=2.97，4/4 月为正。

> 其余候选（5m、中段卡住、长尾淡出、开盘追动量）均未通过成本与稳健性检验。
